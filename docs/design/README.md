## Problem Statement

Snowball Effect에는 최소 플레이 루프와 규칙·Goal 계약이 있지만, Presentation + UI가 어떤 화면을 어떤 순서로 설계하고 제작해야 하는지 연결하는 단일한 생산 체계가 없다. 현재 HUD와 공 렌더링은 기능 확인용에 가깝고, Stage 확장·Merge·Cashout·Scale Shift·Result까지 이어지는 시각 계층과 에셋 우선순위도 여러 문서에 흩어져 있다.

이 문서 세트는 게임 소스를 구현하지 않고 다음을 정한다.

- 유지할 시각 정체성과 변경 가능한 과거 콘셉트의 경계
- 초기 프레임과 확장 1·2·3단계의 화면 구조
- 프레임과 내부 논리 `Play Field`가 함께 넓어지는 계약
- Stage 이름·점수·시간·세로 progressive 공 족보·활성 아이템·Pause를 담는 확정 HUD 정보 계층
- Main Screen, Pause, Settings, 현재 Stage Restart의 화면 흐름
- 공으로 내구도를 깎아 파괴하는 Item Box의 상태와 피드백
- 15개 전역 Ball 등급의 시각 성장 사슬과 Stage별 기본 배치
- Ball·FX·Motion·UI Flow·Stage World의 제작 순서
- S2~S9 Goal 의존성에 맞춘 Presentation 작업 로드맵
- Web 화면과 대량 공 상황을 포함한 시각 검증 방법

## What Makes This Cool

플레이어가 공 하나를 키우는 행위가 아케이드 기계 자체를 밀어내며 세계의 규모를 확장한다. Clear 뒤에는 장식만 바뀌는 것이 아니라 프레임과 실제 플레이 공간이 함께 넓어진다. 좁은 캐비닛에서 시작한 게임이 마지막에는 화면 대부분을 점유하는 우주적 기계로 변하는 것이 핵심적인 “whoa” 순간이다.

## Constraints

- 유지: `90년대 픽셀 아케이드`, 어두운 배경, 대비가 높은 게임 오브젝트.
- 변경 가능: 기존 Stage별 자연·우주 콘셉트의 구체적인 표현, 장식 모티프, 프레임 재질.
- 프레임 폭이 넓어질 때 내부 논리 `Play Field`도 같은 목표 폭으로 넓어진다.
- Stage Shift는 Top Ball/Clear Lock과 Final Settlement가 끝난 뒤에만 진행한다. Black Hole Phase Transition은 Stage Shift가 아니라 Galactic 내부 기믹 발동 전환이다.
- Presentation은 gameplay score/state를 계산하거나 변경하지 않는다.
- 1600×900을 설계 기준으로 삼되 Web의 다양한 화면 크기를 지원한다.
- 엄격한 전체 화면 정수 배율보다 일관된 실루엣·텍셀 밀도·최근접 필터·가독성을 우선한다.
- Frame의 주재료는 짙은 청록 에나멜과 노출 금속이며 녹은 제한된 마모 흔적으로만 사용한다.
- 좌우 HUD/캐비닛 bezel은 고정 폭을 유지하고 Play Field edge와 함께 바깥으로 이동한다.
- 이 문서 작업은 구현 승인이 아니다. Runtime Scene·Script·Resource와 Goal 상태를 변경하지 않는다.

## Premises

### 확정

1. Initial 뒤 Ground Clear에서 L1, Planetary Clear에서 L2, Galactic의 Black Hole 기믹 발동에서 L3로 확장한다.
2. 프레임과 표시용 Play Field는 전환 애니메이션 동안 함께 확장한다.
3. 다음 Stage가 시작될 때 Core의 논리 경계도 같은 목표 Rect를 사용한다.
4. 확장은 화면 중심을 기준으로 좌우 대칭이다.
5. Stage Shift 동안 simulation·spawn·timer는 정지 상태다.
6. Frame·Play Field·Stage World는 하나의 화면 체계로 설계한다.
7. v1 기본 진행은 3개 Stage이며 Stage마다 5등급을 사용하고 경계 Ball 1종을 공유한다. Lv7·Lv9는 visual catalog에는 있지만 기본 Run에서 비활성이다.
8. HUD는 Stage 이름, Stage Score/Target과 Time을 우선하고, 세로 5칸 공 족보를 새 공 생성에 맞춰 공개한다.
9. Item Box는 Ball 충돌로 파괴해 획득한다.
10. V4 `Frozen Enamel Arcade`를 제작 기준으로 사용한다.
11. Main은 우주의 동결된 arcade cabinet, Pause는 단일 maintenance hatch로 표현한다.
12. Merge, Item Box break, Score Milestone의 V4 FX 문법을 유지하고 V5 Black Hole Phase 전환을 추가한다.
13. Lv14 `Black Hole`은 Galactic top Ball이며, 동명 이동 Black Hole 맵 기믹은 별도 Stage가 아닌 Galactic 최종 국면 Stage effect다.

### 튜닝 시작값

1600×900 기준 폭 `600 → 760 → 920 → 1080`을 비교용 시작값으로 사용한다. 이 수치는 balance·spawn density·paddle reach·Web 가독성 검증 후 바꿀 수 있다.

### 미확정

- Stage별 최종 background motif와 개별 cabinet 장식
- 정확한 전환 시간·카메라 진동·hit-stop 값
- Ball 전체 색상표·Audio asset·최종 폰트
- Item Box spawn frequency와 아이템별 최종 balance
- v1 이후 추가 아이템 수와 동시 활성 효과가 3개를 넘을 때의 HUD 확장 방식

## Cross-Model Perspective

독립 검토에서는 “Recursive Cabinet Cosmology”를 제안했다. 이전 Stage의 거대한 세계가 다음 Stage에서는 가장 작은 기본 단위가 되는 감각을 Scale Shift의 중심으로 삼고, 1600×900 North-star keyframe, 네 단계 비교판, Shift storyboard/animatic, Ball hierarchy bible, FX tier matrix를 먼저 만드는 접근이다.

이 의견에서 채택한 것은 **프레임 확장을 장식 교체가 아니라 세계 규모 변화로 보여주는 원칙**과 **프레임 단계 비교판을 먼저 검증하는 방식**이다. 구체적인 우주 서사와 에셋 표현은 아직 확정하지 않는다.

## Approaches Considered

### Approach A: Single Master Document

한 파일에 모든 디자인 규칙과 할 일을 모은다. 빠르게 시작할 수 있지만 HUD·FX·Stage World·Goal handoff가 커질수록 변경 영향과 책임이 불명확해진다.

### Approach B: Production Design System — 선택

기초 원칙, 화면/HUD, Frame/Stage World, Ball/FX/Motion, UI Flow, Asset Production, Goal Roadmap, Validation을 분리한다. 각 문서는 확정·튜닝·미확정 상태와 Owner/Integration handoff를 함께 기록한다.

### Approach C: Showpiece First

Scale Shift animatic과 한 장의 강한 keyframe을 먼저 만든 뒤 나머지를 역설계한다. 데모 임팩트는 빠르게 확인할 수 있지만 현재 S2부터 시작하는 Goal 의존성과 일상 HUD/feedback의 기반을 놓칠 위험이 있다.

## Recommended Approach

Approach B를 사용한다. 구조적 계약을 먼저 고정하되 아트 주제와 HUD 내용은 교체 가능하게 유지한다. Scale Shift keyframe과 storyboard는 시스템의 첫 번째 고가치 시각 산출물로 포함하되, S2-G5 Merge FX와 score presentation 준비를 건너뛰지 않는다.

### Decision rule

`Blocking = YES`인 항목이 해결되지 않았으면 관련 Goal을 `IN PROGRESS`로 올리지 않는다. 결정이 기존 slice verification과 다르면 `docs/goals/slices/`와 참조 task/Integration contract를 함께 갱신한다.

## Success Criteria

- 정지 화면을 5초 본 사람이 Paddle, gameplay ball, 열린 Cashout 방향을 구분한다.
- 두 번의 Stage Shift와 한 번의 Black Hole Phase Transition에서 프레임과 내부 공간이 넓어졌다는 사실이 장식 변화보다 먼저 읽힌다.
- Frame 표시와 Core logical bounds가 하나의 Stage profile에서 같은 목표 Rect를 사용한다.
- HUD의 authoritative 값과 아이템 수가 바뀌어도 Frame·Play Field·Stage World 구조를 다시 설계하지 않는다.
- Merge/Cashout/Clear feedback이 대량 공 상황에서도 핵심 오브젝트를 가리지 않는다.
- Item Box의 희귀도·내구도·획득·놓침 상태가 색 없이도 구분된다.
- 15개 Ball을 크기·outline·motif로 정렬할 수 있고 기본 13종 배치가 Stage마다 이어지며, Lv14 Black Hole Ball과 동명 이동 Black Hole 맵 기믹이 서로 다른 runtime entity로 읽힌다.
- 1600×900, 1280×720, 1366×768, 1920×1080에서 필수 텍스트와 조작 대상이 읽힌다.
- 각 산출물에 Owner, dependency, verification, 의도적 제외 범위가 기록된다.

## Distribution Plan

최종 게임은 기존 Godot Web export와 public build 흐름을 따른다. 디자인 산출물은 이 저장소의 `docs/design/`에서 version control하며, 실제 runtime asset과 scene은 각 Goal이 승인·활성화된 뒤 해당 Owned Files에 제작한다.
